# PaddleOCR replacement research

Checked 2026-11-04. These are source-backed options, not a claim of runtime qualification.

Paddle's [multilingual PP-OCRv5 documentation](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/algorithm/PP-OCRv5/PP-OCRv5_multi_languages.en.md) lists Arabic and English for its Arabic mobile recognizer. Its [current general OCR documentation](https://github.com/PaddlePaddle/PaddleOCR/blob/main/docs/version3.x/pipeline_usage/OCR.en.md) identifies PP-OCRv6 as the default but excludes Arabic from the v6 recognition language list. The v5 Arabic recognizer is therefore the documented choice for a single Arabic and English model; quality, bidirectional reading order and mixed-language lines still need actual screenshot tests.

[OAR-OCR](https://github.com/GreatV/oar-ocr) offers native Rust Paddle-compatible detection, cropping and recognition. Its [model guide](https://github.com/GreatV/oar-ocr/blob/main/docs/models.md) lists third-party converted ONNX assets. GitHub's [v0.3.0 release metadata](https://github.com/GreatV/oar-ocr/releases/tag/v0.3.0) and the [model registry](https://github.com/GreatV/oar-ocr/blob/main/oar-ocr-core/src/core/download/registry.rs) agree on these hashes and lengths; no assets were downloaded or hashes independently recomputed:

Paddle publishes the [original Arabic inference bundle](https://paddle-model-ecology.bj.bcebos.com/paddlex/official_inference_model/paddle3.0.0/arabic_PP-OCRv5_mobile_rec_infer.tar); ONNX release assets are separately converted, not byte-identical to this bundle. [PaddleOCR](https://github.com/PaddlePaddle/PaddleOCR/blob/main/LICENSE) and [OAR-OCR](https://github.com/GreatV/oar-ocr/blob/main/LICENSE) code are Apache-2.0. Confirm model-specific redistribution terms and attribution separately.

The [OAR features guide](https://github.com/GreatV/oar-ocr/blob/main/docs/features.md) describes CPU and optional CUDA inference. Disable build-time runtime downloads and implicit model downloads to use this repository's checksum-verified catalog. Its [manifest](https://github.com/GreatV/oar-ocr/blob/main/Cargo.toml) pins ort 2.0.0-rc.13 and requires Rust 1.95. The repository already catalogs Sherpa CPU and CUDA runtime archives; its CUDA archive name identifies ONNX Runtime 1.28.2. Check the actual libraries, dynamic loader paths, ABI compatibility and provider execution on a real device before asserting reuse or GPU success.

The [ONNX Runtime CUDA requirements](https://onnxruntime.ai/docs/execution-providers/CUDA-ExecutionProvider.html) specify CUDA 13 and cuDNN 9 for its 1.28 CUDA 13 builds. The existing CUDA dependencies are much larger than the approximately 12.9 MB of OCR model assets. The OAR CUDA provider registration does not currently force errors on registration failure, and ONNX Runtime may fall back to CPU: GPU availability alone does not prove GPU execution. Strict GPU selection needs explicit failure handling and real-device verification.

Paddle's [Arabic recognition decoder](https://github.com/PaddlePaddle/PaddleOCR/blob/dab3fe35379033fdcb2d0e9572fac0b36c9a9ebf/ppocr/postprocess/rec_postprocess.py#L44-L67) enables a reversal step for an Arabic dictionary and preserves contiguous ASCII letter, digit, space and selected punctuation runs. OAR's [decoder](https://github.com/GreatV/oar-ocr/blob/main/oar-ocr-core/src/processors/decode.rs) contains a similar private function, but its constructors set the private reversal flag to false. The reader applies this rule to detected Arabic-containing lines, with the intentional extension of keeping Arabic vowel marks attached to their preceding base character. Mixed-script line order and recognition quality still require fixture testing.
