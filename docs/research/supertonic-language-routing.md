# Supertonic 3 and automatic language routing

Research checked 2026-11-04. “Supersonic” most likely means Supertone's **Supertonic**; this is an inference from the requested TTS use case. Confirm the name if another model was intended.

## Model and implementation

[Supertonic 3](https://huggingface.co/supertone-oss-archive/supertonic-3) is an offline ONNX model with 31 languages, explicitly including Arabic (`ar`) and English (`en`); Supertonic 2 supported five languages, so version matters. The [upstream project](https://github.com/supertone-oss-archive/supertonic) is archived and no longer receives official development/support. The model card identifies OpenRAIL-M for weights and MIT for example code; review the [actual model license](https://huggingface.co/supertone-oss-archive/supertonic-3/blob/aafc6e32416a594460b32413efc49d7fe4ce6d46/LICENSE) before redistribution.

The [official Rust example](https://github.com/supertone-oss-archive/supertonic/tree/main/rust) implements ONNX inference. More directly relevant to the existing sherpa C interface, [sherpa-onnx documents native Supertonic 3 support](https://k2-fsa.github.io/sherpa/onnx/tts/supertonic.html), including language and speaker selection and an INT8 package. The [v1.13.8 C header](https://github.com/k2-fsa/sherpa-onnx/blob/v1.13.8/sherpa-onnx/c-api/c-api.h) already includes the Supertonic fields present in this worker. Its [version-pinned Rust example](https://github.com/k2-fsa/sherpa-onnx/blob/v1.13.8/rust-api-examples/examples/supertonic_tts.rs) uses four INT8 models, `tts.json`, `unicode_indexer.bin` and `voice.bin` from the sherpa-converted archive; upstream raw JSON styles are not a drop-in replacement. Verify that language can be set per synthesis call and that the actual packaged binary has the needed provider; do not assume the presence of a GPU provider from API support alone. The published [INT8 archive](https://github.com/k2-fsa/sherpa-onnx/releases/download/tts-models/sherpa-onnx-supertonic-3-tts-int8-2026-05-11.tar.bz2) is a separate conversion from sherpa; verify its release checksum, licensing and pronunciation before adopting it.

Upstream prescribes the archived model at revision `aafc6e32416a594460b32413efc49d7fe4ce6d46`. The [Hub metadata API](https://huggingface.co/api/models/supertone-oss-archive/supertonic-3?blobs=true) reports these file sizes and SHA-256 values for LFS objects. Download URLs are `https://huggingface.co/supertone-oss-archive/supertonic-3/resolve/aafc6e32416a594460b32413efc49d7fe4ce6d46/onnx/<filename>`.

Also required are `onnx/tts.json`, `onnx/unicode_indexer.json`, and selected `voice_styles/*.json` at the same revision. Obtain and pin SHA-256 for those small files independently; the API did not expose LFS SHA-256 for them. ONNX files total about 398 MB decimal, before styles and runtime. Do not equate file size with peak RAM or VRAM.

[ONNX Runtime](https://onnxruntime.ai/docs/execution-providers/CUDA-ExecutionProvider.html) publishes GPU builds but requires matching CUDA and cuDNN versions. CPU is a viable baseline. For a 4 GB GPU, do not promise fit or force GPU: keep only the active TTS model resident, unload at idle or model switch, handle provider initialization/out-of-memory failures with explicit CPU fallback, and measure peak VRAM alongside the existing STT process with long inputs. Validate actual release binaries and dynamic library dependencies on each OS.

## Language detection and product policy

The upstream [`na` language](https://github.com/supertone-oss-archive/supertonic) is language-agnostic processing, not a detected language: it cannot choose between Kokoro and Supertonic by itself. Default to automatic *text* language selection; retain explicit single-model and keyboard modes. Route English to Kokoro, Arabic and the other supported Supertonic languages to Supertonic by default. Provide one general fallback model and a compact searchable list of optional language-to-model/voice overrides; unspecified languages inherit the fallback. Persist explicit existing settings rather than silently replacing an established user choice during migration.

[Lingua's Rust implementation](https://github.com/pemistahl/lingua-rs) is offline, supports Arabic and English, returns confidence values, can return unknown, and includes experimental mixed-language segmentation. It uses character n-grams and rules; its own documentation explains short input is intrinsically less reliable and low-accuracy mode reduces short-text accuracy. Do not mistake Arabic script for Arabic language: Persian and Urdu also use it. Restrict candidate languages only when justified by product configuration; otherwise out-of-set text can be misclassified. Calibrate confidence and minimum text length using actual examples rather than inventing a threshold.

Split paragraphs/sentences and preserve ordering and punctuation. Consider language spans for genuinely mixed Arabic/English text, but avoid switching models for isolated acronyms, URLs, code, numbers, punctuation or low-confidence fragments; inherit neighboring language when safe. For unknown/unsupported input, use the user-selected general fallback; Sherpa v1.13.8 explicitly rejects `na`: its [implementation](https://github.com/k2-fsa/sherpa-onnx/blob/v1.13.8/sherpa-onnx/csrc/offline-tts-supertonic-impl.cc) accepts only its 31 listed codes. A fallback must therefore select a supported explicit language or another engine. Never silently discard text. Keep explicit keyboard and single modes authoritative. An observable fallback indication and user override handle ambiguous short text without blocking playback. Whether to split spans or synthesize a whole utterance must be verified by listening for pauses and pronunciation.

## Validation

Test settings migration, detection and routing with Arabic, English, mixed sentences, unsupported languages, Arabic-script Persian/Urdu, one-word inputs, numbers, URLs, code, emoji, empty input and failed/missing models. Verify overrides, fallback, explicit modes and text preservation. Integration-test real synthesis in both engines, per-call language/speaker, cancellation, switching, process lifecycle, offline operation and missing runtime. Listen to mixed speech; benchmark first audio, throughput, memory and peak VRAM including concurrent STT on representative 4 GB hardware. Compare CPU and real GPU builds and exercise unavailable provider and out-of-memory fallback. Neither synthesized quality nor memory fit has been measured by this research.
