# Dictation workflow research

Checked 2026-11-04. These are individual first-party reports, documentation, and release notes, not a representative prevalence survey. Product-specific causes do not establish bugs in Simple STT.

## Observations and existing coverage

- **Speech boundaries:** A VoiceInk user reports losing the last word on release and proposes 300 ms of post-roll, at the cost of 300 ms latency; the issue remains open ([#1025](https://github.com/Beingpax/VoiceInk/issues/1025)). Handy merged a tail-audio fix in August and lists it in v0.9.7 ([PR #1958](https://github.com/cjpais/Handy/pull/1958), [release notes](https://github.com/cjpais/Handy/releases)). Separately, a VoiceInk user reports missing initial speech; the issue was reopened after a partial device workaround ([#996](https://github.com/Beingpax/VoiceInk/issues/996)). A fixed delay is a user proposal, not proven appropriate for this app.
- **Clipboard and target app:** One VoiceInk report describes consecutive dictations capturing a previous temporary transcript instead of the original clipboard ([#1024](https://github.com/Beingpax/VoiceInk/issues/1024), open); another reports intermittent Chromium paste failures ([#1000](https://github.com/Beingpax/VoiceInk/issues/1000), open). VoiceInk 2.25 says paste and clipboard restoration were improved, but does not establish that either particular report is resolved ([release notes](https://github.com/Beingpax/VoiceInk/releases)). Wispr's own troubleshooting documents different paste shortcuts, held modifiers, focus and unsupported clipboard formats, and warns that paste submission may not mean insertion ([help](https://docs.wisprflow.ai/articles/7971211038-Fix-text-not-pasting-after-dictation)). Simple STT already has serialized Linux transactions, bounded full-format backups, modifier release gates, target checks and a retry cache; platform limitations remain documented in `docs/architecture.md`.
- **Recovery and feedback:** Handy users describe dictating with no editable field focused and request a shortcut to recover the transcript; another highlights the privacy risk of insertion in the wrong window ([discussion #211](https://github.com/cjpais/Handy/discussions/211)). Wispr documents a separate copy-last shortcut and a paste-last shortcut, plus explicit instructions to release modifiers ([help](https://docs.wisprflow.ai/articles/7971211038-Fix-text-not-pasting-after-dictation)). Simple STT already provides retry, a one-item bounded in-memory cache, target safety, and release/progress feedback. Avoid assuming an unconfirmed paste succeeded or retrying it automatically.
- **Shortcuts:** VoiceInk's modifier-only shortcut report describes missed presses and stale key-up state; the owner closed it November 3 after recovery changes ([#1022](https://github.com/Beingpax/VoiceInk/issues/1022)). Handy users also describe missed toggle transitions and request separate start/stop commands; another requests hybrid hold/double-tap behavior ([discussion #211](https://github.com/cjpais/Handy/discussions/211)). Simple STT already supports hold/toggle and platform-specific routing; validate its own state transitions before adding shortcut modes.
- **Warmth and languages:** A VoiceInk user measured severe first-use delay after idle, with much faster repeated use; the owner closed the original wrong-prewarm/reload issue November 3 while noting separate load-hang recovery concerns ([#1003](https://github.com/Beingpax/VoiceInk/issues/1003)). Handy users request per-shortcut language/model overrides ([discussion #211](https://github.com/cjpais/Handy/discussions/211)). Simple STT already freezes keyboard language per recording, prewarms the selected model while recording, reuses a matching worker, and exits that worker after the idle timeout. Keeping multiple models resident indefinitely would conflict with its memory goal.
- **Long and short clips:** Wispr documents long processing times and recording limits ([help](https://docs.wisprflow.ai/articles/7971211038-Fix-text-not-pasting-after-dictation)). A historical whisper.cpp report described short recordings silently yielding no output; it is closed as not planned and is not evidence of the same behavior in Parakeet ([#1603](https://github.com/ggml-org/whisper.cpp/issues/1603)). Simple STT already surfaces short/no-speech notices. Chunking can affect recognition and ordering and should not be assumed safe across models.

## Recommendations for Simple STT

1. **Measure and validate audio boundaries first.** Add a deterministic test of samples received around stop and a real-device check of immediate first/last words. If actual tail loss is measured, evaluate a small bounded, cancelable post-roll against latency and privacy; do not silently add a 300 ms delay based solely on another app's report. Impact: prevents lost words; scope: capture boundary and tests.
2. **Measure cold versus warm paths by selected model/device.** Record metadata-only timing for start, model readiness, stop, inference and delivery; compare language switches that select the same model versus different models. Reuse one existing worker and preserve idle exit. Impact: directs latency work to a measured bottleneck; scope: bounded diagnostics, no transcript or audio logging.
3. **Make recovery discoverable when delivery is uncertain.** Reuse existing concise notices to mention the configured Retry shortcut when a delivery fails or cannot be verified; offer copy-last only if a concrete gap remains after checking current controls. Preserve a single bounded in-memory item. Impact: helps users recover without a second inference; scope: existing notice and retry path.
4. **Exercise back-to-back non-text clipboard and shortcut-release races.** Verify real insertion and preservation of an image/custom format across consecutive dictations, a newer user copy, and a held shortcut. The architecture already describes protections; this is regression validation, not a claim they are broken. Impact: protects copied data and avoids duplicate text; scope: focused platform tests.
5. **Keep long-dictation feedback bounded and honest.** If measured long inference is a problem, show elapsed processing or an existing concise state before considering streaming/chunking; benchmark accuracy, cancellation, ordering and memory for every supported model first. Impact: improves perceived responsiveness; scope: existing overlay, no network or persistent history.
